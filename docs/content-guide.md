# 内容维护指南

由映像研究部统一操作后台。涉及部门内容的删改先在飞书沟通，并预留 2–3 天以上缓冲。CMS 负责编辑和发布，不承担审批。

## 日常更新

1. 打开正式网站 `/admin/`，使用已有权限的 GitHub 账号登录。
2. 在“网站内容”中选择对应栏目，修改文字、上传图片或调整列表顺序。
3. 检查链接、作者署名和日期，再发布。发布会提交到 `main`，触发 Cloudflare Pages 构建。
4. 等部署成功后刷新前台确认。若构建失败，旧版仍继续服务；维护者查看构建日志，修正指出的字段后再发布。

本地预览中的 GitHub 登录仍指向正式仓库 `main`。测试编辑应使用 Sveltia 的本地目录模式（支持的 Chrome/Edge 中选择项目目录），避免把测试内容发布到线上。真实账号登录和发布需上线时联调。

## 栏目与展示规则

| 后台栏目             | 可管理的内容                     | 前台规则                                     |
| -------------------- | -------------------------------- | -------------------------------------------- |
| 首页、部门与联系方式 | 名称、简介、图片、部门、公开渠道 | 部门按列表顺序；资料整理提示清空后消失       |
| 发展历程             | 年份、标题、说明、图片           | 按列表顺序，建议从早到晚                     |
| 文化、角色与作品     | 社团物语、角色、作品、作者与链接 | 按列表顺序；首页各取前两项推荐角色、推荐作品 |
| 代表活动             | 日期、类别、封面、简介、推文链接 | 自动从新到旧；首页取最新三项推荐活动         |
| 纳新与临时公告       | 时间、地点、文案、展示期限       | 首页内嵌提示，不弹模态窗口                   |

“在网站展示”可以暂时隐藏条目。“首页推荐”只影响首页，不影响条目在所属栏目中的展示。空栏目自动隐藏。隐藏仅指前台展示，仓库中仍保留内容；内部资料继续存飞书。

活动以纳新、周年庆、参与大型校级活动等为主，小活动由公众号发布即可。活动页只有简短记录和链接，不需要重新排一篇站内文章。日期填写 `2026-09-01`；旧资料只确定年份时填写 `2021`，不要补造具体日期。

视频作品填写 B 站等公开链接，图片上传到媒体库，不上传视频原片。作者和届次暂不明确时留空，确认后再补。尽量上传适合网页的图片，保留原件在社团档案中；本站未配置自动压图或转 WebP。

## Markdown 正文

部门介绍、历程说明、社团物语、角色介绍、作品介绍与活动简介支持 Markdown。可在 CMS 的富文本编辑器或源码模式中编辑：段落用空行分开，使用强调、列表、引用与链接表达层次。标题会从三级开始，不覆盖页面主标题。

正文不接受 HTML、脚本或嵌入视频，也不展示 Markdown 图片；图片使用各条目的独立配图字段。外链使用完整 HTTPS 地址，站内链接可写 `/about` 或 `#characters-heading`。简介与历程说明建议简短，完整物语可以分段书写。

工具栏保留当前页面支持的常用排版选项，配置依据 [Sveltia Markdown 编辑器说明](https://sveltiacms.app/en/docs/fields/richtext)。

首页的学院风景属于固定装饰插画；后台“首页社团插画”管理首页文化区域的社团作品及署名，两者分别维护。

## 设置纳新公告

启用前填写编号、标题、活动时间说明、地点，以及开始和停止展示时间。时间选择器使用编辑设备的时区，保存时包含时区偏移；在中国境内通常为 `+08:00`。开始时间必须早于停止时间。

公告在开始时刻出现，在结束时刻隐藏，已经打开的网页也会更新，不需要届时重新部署。该时间判断使用访客设备时钟，适用于通知展示，不用于限制报名资格。访客收起后仍保留一行标题和“展开公告”；修改时间、地点或正文后会重新展开提醒。

结束后可关闭“启用公告”，不必删除代码。下次使用新编号。现有公告默认关闭，没有虚构的纳新时间或地点。

## 联系方式与二维码

“跳转链接”用于按钮；“二维码链接”会在构建时生成二维码，未填跳转链接时也用于按钮。上传了“二维码图片”就优先展示该图片。公众号可上传自己的二维码；生成的二维码不盖头像，以保证识别。

发布前应核对 QQ 群链接仍有效、公众号二维码属于社团、外链能打开。内容中的链接必须为完整 `https://` 地址，图片必须来自 `/uploads/`，缺失图片或非法字段会阻止新版本构建。
