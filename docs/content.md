# 内容维护

后台由映像研究部统一操作。涉及部门内容的删改先在飞书与对应部门沟通，并预留 2–3 天以上缓冲。CMS 只负责编辑和发布，不提供审批流程。

## 日常更新

1. 打开正式网站的 `/admin/`，用有仓库写权限的 GitHub 账号登录。
2. 在“网站内容”中选择栏目，修改文字、上传图片或拖动调整列表顺序。
3. 检查链接、作者署名和日期后发布。发布即提交到 `main`，触发 Cloudflare Pages 构建。
4. 部署成功后刷新前台确认。构建失败时旧版继续服务；查看构建日志，按提示修正字段后再发布。

本地预览中的 GitHub 登录同样指向正式仓库的 `main`。只想试改时，使用 Sveltia 的“使用本地仓库”（Chrome/Edge 中选择项目根目录），避免把测试内容发布到线上。

## 栏目与展示规则

| 后台栏目             | 可管理的内容                     | 前台规则                                     |
| -------------------- | -------------------------------- | -------------------------------------------- |
| 首页、部门与联系方式 | 名称、简介、图片、部门、公开渠道 | 部门按列表顺序；资料整理提示清空后消失       |
| 发展历程             | 年份、标题、说明、配图           | 按列表顺序，建议从早到晚                     |
| 文化、角色与作品     | 社团物语、角色、作品、作者与链接 | 按列表顺序；首页各取前两项推荐角色、推荐作品 |
| 代表活动             | 日期、类别、封面、简介、推文链接 | 自动从新到旧；首页取最新三项推荐活动         |
| 纳新与临时公告       | 时间、地点、文案、展示期限       | 首页内嵌提示条，不弹出窗口                   |

“在网站展示”可暂时隐藏条目，仓库中仍保留内容。“首页推荐”只影响首页。没有内容的栏目自动隐藏。

活动只收录纳新、周年庆、大型校级活动等代表性活动，小活动由公众号发布即可；网站只放简短记录和推文链接，不重新排一篇文章。日期填写 `2026-09-01`；旧资料只确定年份时填写 `2021`，不要补造具体日期。

视频作品填写 B 站等公开链接，不上传视频原片。作者和届次不明确时留空，确认后再补。上传前把图片处理成适合网页的尺寸，原件保留在社团档案中；网站不会自动压缩图片。

首页的学院风景是固定装饰插画，不在后台管理；后台的“首页社团插画”是首页文化区域展示的社团作品，需附说明或署名。

## Markdown 正文

部门介绍、历程说明、社团物语、角色介绍、作品介绍和活动简介支持 Markdown，可在 CMS 的富文本或源码模式中编辑：空行分段，用强调、列表、引用和链接表达层次。正文中的标题从三级开始显示，不会抢占页面标题。

正文不接受 HTML、脚本、嵌入视频或图片；图片使用各条目的配图字段。外链写完整的 `https://` 地址，站内链接可写 `/about` 或 `#characters-heading`。编辑器说明见 [Sveltia 文档](https://sveltiacms.app/en/docs/fields/richtext)。

## 纳新公告

启用前填写编号、标题、活动时间说明、地点，以及开始和停止展示时间。时间选择器使用编辑设备的时区，保存时带时区偏移，在中国境内通常为 `+08:00`。停止时间必须晚于开始时间。

公告在开始时刻出现、结束时刻隐藏，已打开的网页也会按时更新，不需要届时重新发布。判断使用访客设备的时钟，只用于展示通知。访客收起后保留一行标题和“展开公告”；修改时间、地点、标题或正文后会重新展开。

结束后关闭“启用公告”即可，下次使用新的编号。

## 联系方式与二维码

“跳转链接”用于按钮；填写“二维码链接”会在构建时生成二维码，没有跳转链接时也用作按钮链接。上传了“二维码图片”时优先展示图片，适用于公众号。生成的二维码中间不加头像，以保证识别。

发布前确认 QQ 群链接仍有效、公众号二维码属于社团、外链可以打开。链接必须是完整的 `https://` 地址，图片必须来自 `/uploads/`；缺失图片或不合规的字段会让构建失败，线上仍保留旧版。

- 核对完成后清空“资料整理提示”，删去各条目中的待确认说明。
